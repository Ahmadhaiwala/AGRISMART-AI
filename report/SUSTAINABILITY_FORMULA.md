# Sustainability Score — Formula (Bonus Module D)

## Inputs
| Field | Meaning |
|---|---|
| `water_used_liters` | Water actually applied |
| `water_required_liters` | Crop's estimated water requirement |
| `fertilizer_used_kg` / `fertilizer_recommended_kg` | Fertilizer applied vs. recommended |
| `pesticide_used_kg` / `pesticide_recommended_kg` | Pesticide applied vs. recommended (optional) |
| `is_healthy`, `disease_confidence` | From the core disease-detection model (Module A); confidence used as a severity proxy when diseased |

## Sub-scores (0–100 each)

**Water efficiency** — penalizes both over- and under-watering:
```
water_efficiency = 100 * (1 - |used - required| / required)
```

**Resource use** — same efficiency formula applied to fertilizer (and pesticide, if provided), then averaged:
```
fertilizer_efficiency = 100 * (1 - |used - recommended| / recommended)
resource_use = average(fertilizer_efficiency, pesticide_efficiency)
```

**Crop health** — from the disease-detection model's output:
```
crop_health = 100                          if healthy
crop_health = 100 * (1 - disease_confidence)   if diseased
```

## Overall score
```
overall_score = 0.4 * water_efficiency + 0.3 * resource_use + 0.3 * crop_health
```

## Grade bands
| Score | Grade |
|---|---|
| ≥ 80 | A |
| ≥ 60 | B |
| ≥ 40 | C |
| < 40 | D |

## Improvement suggestions
Generated by checking which sub-score is below 70 and identifying the
direction of the problem (e.g. over- vs. under-watering, over- vs.
under-fertilizing, disease present) — see `service.py` for the exact rules.

## Why this design
- All rules are fixed constants (weights: 0.4 / 0.3 / 0.3), not a trained
  model — this keeps the score fully reproducible and auditable, as required
  by the evaluation rubric (Sustainability & Social Impact axis).
- Both over-use and under-use of water/fertilizer are penalized, since
  neither extreme is sustainable.
- Decoupled from other bonus modules: works today with manually entered
  values, and will work unchanged once Modules B (irrigation) and C
  (weather) exist — their outputs simply become better sources for
  `water_required_liters`.
